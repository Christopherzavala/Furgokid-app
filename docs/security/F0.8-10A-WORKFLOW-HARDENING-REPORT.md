## Condición externa y limitación

El YAML asigna el job al Environment `eas-build`, pero no puede establecer sus protecciones. Antes de cualquier build con credenciales, un administrador del repo debe:

1. Configurar el Environment `eas-build` para aceptar únicamente `main` protegida y requerir aprobación humana.
2. Mover `EAS_TOKEN` a un secreto de ese Environment y quitarlo de repository/org scopes accesibles a refs no confiables.
3. Confirmar en GitHub la protección de `main` y de los workflows; dejar evidencia comprobable.

No se consultó ni cambió configuración remota. El build no se ejecutó y no se afirma que el Environment o los secrets estén configurados correctamente. Por eso 10A está verificado como cambio local estático, pero el gate de credenciales permanece bloqueado.
